# Bounded Agent & Model Context Protocol (MCP) Guide

## 1. The Bounded Agent Philosophy

Traditional autonomous agents are prone to hallucinated tool invocations, runaway API token consumption, and prompt-injection jailbreaks.
EKIP implements a **strictly bounded agent** designed for safe, predictable developer assistance.

### Core Guarantees:
1. **RAG by Default**: Pure knowledge queries *never* trigger the agent. The agent path is only activated when an operational action (e.g., drafting an operational checklist) is explicitly identified.
2. **Hard Loop Ceiling**: The agent reasoning loop is capped at a maximum of **5 iterations** (`app/agents/agent.py`). It is impossible for EKIP to enter an infinite loop.
3. **Pre-Call Tool Allowlist**: Before invoking any tool, `app/core/permissions.py` verifies whether the tool is explicitly authorized. The model's claim that a tool is "safe" is rejected.
4. **Human-in-the-Loop DRAFTS**: All outputs generated by the agent are designated as non-executable drafts for human review. EKIP has **zero direct write access** to production systems, databases, or cloud providers.

## 2. Fast-Path Pre-Flight Relevance & Rejection

To prevent prompt injection and wasted inference credits:

```
User Query: "Draft me a step-by-step guide for a mattar paneer recipe"
                                │
                                ▼
         ┌──────────────────────────────────────────────┐
         │ Fast-Path Pre-Flight Knowledge Verification  │
         │ - Queries active vector sub-databases        │
         │ - Evaluates minimum score threshold (>= 0.35)│
         └──────────────────────┬───────────────────────┘
                                │
                 Found 0 matching runbooks?
                                │
             ┌──────────────────┴──────────────────┐
             ▼ YES                                 ▼ NO
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Rejection (< 2 seconds):      │     │ Proceed to Intent Classifier  │
│ - Zero MCP subprocess spawned │     │ & Bounded Agent Execution     │
│ - Zero runaway loops          │     └───────────────────────────────┘
│ - Graded: INSUFFICIENT        │
│ - Polite refusal returned     │
└───────────────────────────────┘
```

This ensures out-of-scope requests (cooking, general trivia, prompt injection) are terminated in under 2 seconds rather than spinning up multi-step agent reasoning loops.

---

## 3. Dynamic Evidence Status Grading

Rather than hardcoding evidence outcomes, the agent path dynamically evaluates supporting context:
- `SUFFICIENT EVIDENCE`: Documented runbooks were discovered, verified, and cited in the drafted procedure.
- `PARTIAL EVIDENCE`: General context exists, but specific rollback steps or configurations are unverified.
- `INSUFFICIENT EVIDENCE`: No supporting operational documentation exists; refusal or missing information is explicitly stated.

## 4. Model Context Protocol (MCP) Integration

EKIP decouples tool execution from the application core using the **Model Context Protocol (MCP)**:

```
┌─────────────────────────────────┐                 ┌─────────────────────────────────┐
│       EKIP Main Process         │                 │   Standalone MCP Subprocess     │
│    (FastAPI / Streamlit)        │                 │      (mcp_server/server.py)     │
│                                 │   stdio JSON-RPC│                                 │
│  ┌───────────────────────────┐  │   Transport     │  ┌───────────────────────────┐  │
│  │     MCP Client Bridge     │◀─┼─────────────────┼─▶│       MCP Server          │  │
│  │    (app/mcp/client.py)    │  │                 │  │   Tool: search_runbook    │  │
│  └───────────────────────────┘  │                 │  └───────────────────────────┘  │
└─────────────────────────────────┘                 └─────────────────────────────────┘
```

### Why Decouple with MCP?
- **Process Isolation**: Tool execution runs in a sandboxed child process via standard JSON-RPC stdio. A failure or crash in tool execution cannot corrupt the core application.
- **Protocol Standardization**: Any external MCP-compatible assistant (e.g., Claude Desktop, Cursor, or internal IDE plugins) can connect directly to EKIP's standalone server (`mcp_server/server.py`).

### Testing the Standalone MCP Server
You can launch the standalone MCP server directly over stdio:
```bash
uv run python -m mcp_server.server
```
Or run the dedicated MCP integration unit tests:
```bash
uv run pytest tests/unit/test_mcp.py
```
